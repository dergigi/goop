# Goop 2.15.2 validation

## Scope

Reduce outgoing-message delays caused by older queued work and waiting for all relay acknowledgements. Reserve bounded worker capacity for new sends, pause new history signer requests during fresh outgoing preparation, persist early relay acknowledgements, and track activity per message. Read a single outgoing record when enqueueing instead of rereading the full store.

## Local checks

- 81 chat tests and 21 state tests passed.
- A new send completed while an older signer request remained deliberately blocked; retrying the older message did not create a concurrent duplicate writer.
- A successful relay acknowledgement was persisted and reported while a second relay remained deliberately blocked. Remaining delivery stayed pending and reused the same gift wrap.
- History priority guard tests covered multiple sends, cancellation, logout, and a new account session.
- Existing refusal, restart, durable intent/wrap, partial relay retry, account-stop, and storage-recovery regressions passed.
- Release-tool tests: 6 passed. Linux installer tests: 11 passed.
- Optimized macOS candidate installed locally and launched. No claim of user-confirmed latency or real external-signer interoperability testing is made.

## Limits

The change removes local scheduling delays. Signer approval, recipient inbox discovery, and network availability can still delay a send. Already-running history signer requests are allowed to finish. Delivery checks mean relay acceptance, not read receipts. New sends use two slots and backlog work uses one slot, so bursts remain bounded.
